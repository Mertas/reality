# CONTRACTS — контракты модулей и правила сборки

Проект: `E:/My/Reality` — статический сайт **без сборки и без внешних зависимостей**.
Открывается двойным кликом по `index.html` (file://) и через `python -m http.server 1836`.

## 0. Общие правила (обязательны для всех модулей)

- **Стек:** чистые HTML/CSS/JS. Классические `<script>` (НЕ ES-модули) — чтобы работало и по file://. Никаких CDN, шрифтов из сети, библиотек, `fetch` к внешним ресурсам.
- Каждый модуль кладёт себя в глобальный `window.*` и не ломается, если соседний модуль не загрузился.
- **Язык интерфейса — русский.** Тон: спокойный, без восклицаний, без эмодзи, без «вау». В инструкциях к практикам — обращение на «ты»; в аналитических текстах — нейтрально.
- **Палитра и типографика — только через CSS-токены** (ниже). Не задавать глобальный фон/шрифт у `body`. Свои стили — в собственном файле, классы с префиксом своего модуля (`demo-`, `practice-`).
- Не редактировать чужие файлы: `css/style.css`, `js/app.js`, `index.html` — принадлежат родительскому агенту. Свои файлы — только те, что указаны в твоей задаче.
- Проверка перед сдачей: `node --check js/<файл>.js` (синтаксис). Если доступен браузер — открыть тестовую страницу и проверить в консоли отсутствие ошибок.
- Никакого выдуманного контента: все факты/цитаты — из `docs/essay.md` и `docs/agents/*.md`.

## 2. index.html — порядок загрузки (информация; файл не трогать)

```
css/style.css, css/demos.css, css/practice.css
js/data.js → js/demos.js → js/practice.js → js/app.js
```

`app.js` при загрузке рендерит главы из `REALITY_DATA` и вызывает:
- для слота с `data-demo-id="<id>"`: `Demos.mount(id, slotEl, opts)`
- для главы «Практика»: `Practice.init(sectionEl, REALITY_DATA)`

## 4. Контракт `js/demos.js` (окно: `window.Demos`) + `css/demos.css`

```js
window.Demos = {
  items: { /* id → { id, title, mount(el, opts) } */ },
  mount(id, el, opts) { /* создаёт экземпляр, чистит el, возвращает instance (или null) */ },
  has(id) { return !!this.items[id]; }
};
```

Требования: **несколько независимых экземпляров** одного демо на странице (никаких глобальных переменных); у экземпляра метод `destroy()` (остановить rAF, снять слушатели); `opts.onComplete(payload)` — необязательный колбэк; всё рисуется внутри переданного `el`. `devicePixelRatio` учитывать. Никаких алертов.

Демо-модули (7):

1. **`troxler`** — «Гаснущие пятна». Canvas: центральный крест + 6–10 периферийных цветных пятен. Инструкция: зафиксируй взгляд на кресте, не двигай глазами. Если мышь/взгляд не двигается N секунд (старт ~20с, настраивать слайдером 5–40с) — пятна плавно гаснут; движение мыши возвращает. Подпись: «упрощённая реплика; оригинал — Трокслер, 1804».
2. **`blindspot`** — «Найди своё слепое пятно». Два объекта (крест и точка) на горизонтали; слайдер регулирует расстояние; инструкция: закрой правый глаз, смотри на крест левым, найди положение, где точка исчезает. Показывать текущий отступ; пояснение ~12–15°.
3. **`gorilla`** — «Горилла». Canvas-сцена: 4 фигуры (2 светлых, 2 тёмных) двигаются и перебрасывают мяч (светлые — между собой, тёмные — между собой). Задача на экране: «считай передачи светлой команды». Через ~8–10 передач белых или 40с — горилла (тёмная фигура с контуром) проходит через сцену за ~5 с. Затем — стоп и вопросы: «Заметили ли вы что-то необычное?» (да/нет) и «Сколько передач насчитали?» (число). Показать факт (число передач + была горилла) и кнопку «Повтор с подсказкой» (повтор в 0.6× скорости, горилла подсвечена). Финальная подпись: Саймонс—Чабрис, 1999: 46% не замечают; «ни один из незаметивших не „вспомнил“ гориллу, пока запись не прокрутили заново». Это демонстрация «второй модели».
4. **`netineti`** — «Нети нети». Чипсы-содержания: Цвет · Звук · Мысль · Эмоция · Тело · «Я» · Мир. Клик по чипсу — убрать. Каждое удаление даёт спокойную строку-комментарий (из традиций: «не это»), и на «полотне» сцены гаснет соответствующая деталь. Когда убрано всё — финальная панель: «Осталось то, чем всё это замечалось. Попробуй убрать и его — но чем ты это увидишь?» Кнопка «Вернуть всё».
5. **`looking`** — «Посмотри на то, что смотрит». Тихий экран: кнопка «Начать 90 секунд», затем медленная пульсация круга и три строки, сменяющие друг друга: «Не ищи объект» → «Всё, что находится, — уже объект» → «Что не находится?». Таймер виден, можно завершить раньше. По завершении — поле для заметки (textarea) и кнопка «Сохранить в дневник» → если есть `window.Practice && Practice.addJournal` — вызвать; иначе показать «дневник доступен в главе Практика». `opts.onComplete({seconds, note})`.
6. **`contrast`** — «Нет фона — нет фигуры». Простая сцена (фигура на фоне); слайдер «контраст» от 100% до 0%: при 0 фигура исчезает. Подпись: «информация — различие, которое создаёт различие (Бейтсон); константа не несёт бит».
7. **`cut`** — «Разрез фон Неймана». Горизонтальная цепь: атом → прибор → глаз → мозг → сознание → ?. Слайдер двигает «разрез»; подпись под цепью меняется: «здесь?», «или здесь?», «физика не указывает место — разрез задаём мы». Финальное состояние «?»: «эксперимент не найдёт место разреза».

Все тексты демо — на русском, в общем тоне. Код — читаемый, с короткими комментариями по-русски. Размер демо-анимаций — сеткой внутри контейнера (не фикс. ширина), адаптивно.

**Раскладка демо по главам** (для `data.js` и `app.js`): слой 1 → `troxler`; слой 2 → `blindspot`; слой 3 → без демо; слой 4 → `contrast`; слой 5 → `cut`; маршрут 1 → `netineti`; маршрут 3 → `looking`; маршрут 4 → `gorilla` (маршрут 2 — без демо).

## 5. Контракт `js/practice.js` (окно: `window.Practice`) + `css/practice.css`

```js
window.Practice = {
  init(rootEl, data),           // рендер модуля в rootEl; data = REALITY_DATA
  addJournal(prompt, text),     // добавить запись (используется демо)
  getState()                    // состояние (для отладки/экспорта)
};
```

Состав модуля (глава «Практика» — жизнеобразующее ядро сайта):

1. **«Сегодня»:** дата; серия дней подряд (streak); «вода дня» — строка из `data.water`, детерминированно по дате (hash даты → индекс), кнопка «скопировать»; чек-лист практик из `data.practice`: название, зачем (одна строка), «как» (сворачиваемо), чекбокс «сделано»; у практик с `demoId` — кнопка «Открыть демо» → `window.App && App.openDemo(demoId)`.
2. **Дневник:** список записей (дата · промпт · текст), добавление записи (textarea), ротация промптов по времени суток: до 12:00 — утренние («Что сегодня может оказаться водой?»), 12:00–17:00 — дневные, после — вечерние («Что сегодня было очевидным — а я не увидел?»). Минимум 3 промпта на слот.
3. **Экспорт и сброс:** экспорт дневника в `.md` (заголовок: серия дней, всего дней, статистика практик; затем записи) — скачивание через Blob; экспорт `.json`; сброс с двойным подтверждением.

Состояние в localStorage, ключ `reality.practice.v1`:

```js
{ v:1, start:'ISO', days:{ 'YYYY-MM-DD': { marks:['blindspot', ...], note:'' } },
  journal:[ { ts:'ISO', prompt:'...', text:'...' } ] }
```

Требования: без зависимостей; работает и по file:// (localStorage доступен); пустые состояния — вежливые; числа честные (ничего не «накручивать»); мобильная вёрстка. Все интервалы/лимиты — разумные (запись пустой не сохранять; лимит дневника не нужен).
